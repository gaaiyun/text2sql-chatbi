# 评测

## 方法

- **评测集**：`text2sql/datasets/znjz/benchmark.jsonl`，62 题。55 道应答题覆盖分布、排名、趋势、条件筛选、区间与占比、
  存在性与反连接、多表关联、明细检索和 9 道长尾复杂题，每题附手写标准 SQL；7 道应拒题包括写操作、注入、个人信息和领域外问题。
- **判分**：分别执行标准 SQL 与系统生成的 SQL，比较结果集而不是 SQL 文本。按列签名匹配投影列，列名和列顺序无关；
  数值保留两位小数；除排名类题目外忽略行序。
- **指标**：覆盖率 = 作答 / 应答；作答精确率 = 作答且正确 / 作答；执行准确率（EX）= 正确 / 应答；拒答准确率 = 正确拒答 / 应拒；
  Schema 召回率 = 标准答案用到的表被召回的比例。
- **运行**：离线路径 `python -m text2sql eval --write-report`（CI 门禁：作答精确率 ≥ 95%、拒答准确率 100%、覆盖率 ≥ 60%）；
  双路径需要模型，下表的运行经本站 Worker 调用 Cloudflare Workers AI。

## 结论

| 路径 | 覆盖率 | 作答精确率 | 执行准确率 | 拒答准确率 | 模型调用 / token |
|---|---:|---:|---:|---:|---:|
| 离线语义层 | 83.6% | 100% | 83.6% | 100% | 0 / 0 |
| 语义层优先，Workers AI 兜底 | 100% | 98.2% | 98.2% | 100% | 34 / 124,753 |

语义层答不了就放弃，不会答错；放弃的 9 道长尾题交给 SQL 智能体后答对 8 道。
剩下的一题（各城市获得融资的企业占比）模型自行加了“企业数不少于 50”的门槛，只返回 7 个城市。

同一评测集上的第一轮双路径运行里有三处问题，修正后得到上表，修正都是通用的：

| 第一轮现象 | 修正 |
|---|---|
| 问法定代表人的姓名和电话，模型拒绝写 SQL，系统记为“执行失败”，拒答准确率 85.7% | 意图预检在规划前拒绝个人信息请求，不再进入任何规划器 |
| “资质数量超过 10 条的企业有多少家”返回 128 行、每行都是 1 | 执行后诊断“计数问题按分组返回多行 1”，进入修复回路 |
| 模型自行添加 HAVING 门槛 | 提示词增加硬性约束（这一题在第二轮仍然出现，模型没有遵守） |

**局限**：评测集与语义层出自同一作者，离线路径的数字适合做回归门禁，不代表对陌生问题的泛化；
双路径的数字受模型版本与采样影响，两轮之间的差异里也包含这部分波动。开源数据集（Northwind 等）没有标准答案集，
目前只做了在线抽查，未计入上表。
